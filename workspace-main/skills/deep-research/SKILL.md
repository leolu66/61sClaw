# Deep Research 深度研究工具

基于AI和多搜索源的自动化深度研究系统，支持 火山引擎、Firecrawl、多引擎Web抓取、百度、Brave 五种搜索源自动 failover。通过「提示词扩写 → 问题分析 → 维度确认 → 反思审核 → 计划细化 → 报告大纲 → 素材收集 → 按计划搜索 → 生成报告」的完整流程，深入挖掘研究主题，生成高质量结构化报告。支持断点续传、搜索成功率监控、进度条/ETA 显示。

# 功能特性

- 🎯 提示词扩写：针对 AI 技术/产品类主题，自动识别研究方向并扩写为结构化研究任务书
  - **方向 A 市场雷达**：发现热点、识别趋势、筛选值得跟踪的信号，生成含关注来源/筛选标准/具体任务的研究简报
  - **方向 B 技术拆解**：对热点产品/技术做深度剖析，解释其为什么火、怎么做、和谁竞争、壁垒在哪（4层：热点归因/技术拆解/产品拆解/竞争趋势判断）
- 🧠 问题分析与执行计划：AI 自动分析研究问题，匹配预设研究角度模板（对比评估/技术调研/市场分析/综述研究），生成专业研究维度
- ✅ 维度确认与反思审核：用户可增删/调整维度优先级；AI 审核人角色自动检查覆盖盲区、重叠、歧义并追问
- 📋 报告大纲：搜索前先生成报告章节结构，用户确认后按大纲填充内容，报告结构更清晰
- 📚 多源素材收集：支持用户指定参考网页 URL、本地文件（md/pdf/docx/html/pptx/xlsx），自动收集 Obsidian 笔记作为预加载素材，AI 提取关键信息后与网络搜索结果合并
- 📁 研究归档：每次研究自动建立独立目录（src/work/output），保存全流程产物（素材、分析、计划、learnings、报告），实现研究过程可追溯
- 💾 搜索缓存：相同查询结果本地缓存（MD5 文件名，默认 TTL 24h），避免重复搜索
- ⚡ 并发控制：全局可配置并发数（默认3，范围1-10），维度间+维度内并行搜索
- 🔄 断点续传：每步产物自动持久化到 work/*.json，研究中断后可通过 --resume 从上次中断处继续
- 📊 搜索监控：实时统计各搜索源成功率，低于 50% 时自动告警
- 📈 进度条/ETA：按计划搜索阶段显示 Unicode 进度条和预估剩余时间
- 🏗️ 精细化错误处理：每步独立 try-catch，关键步骤失败才 abort，非关键步骤失败自动跳过
- 🔌 代理检测缓存：Clash 代理检测结果缓存，避免重复 HTTP 请求
- 🔍 智能搜索：自动生成相关搜索查询，并行执行搜索，多搜索源自动 failover（火山引擎 → Firecrawl → 多引擎抓取 → 百度 → Brave）
- 🤖 自动化深度研究：多轮递归搜索，深入挖掘相关信息
- 📝 结构化输出：按计划驱动生成详细、结构化的研究报告
- 🎯 需求确认：通过多轮问答获取用户详细研究需求
- ⚙️ 可配置参数：支持自定义研究广度/深度、并发数、缓存策略、素材来源
- 💾 自动保存：报告自动保存到归档目录和 output/ 目录

## 环境要求

需要配置以下环境变量：
- `FIRECRAWL_API_KEY`：Firecrawl API 密钥（已配置）
- `VOLCSEARCH_API_KEY`：火山引擎融合搜索 API Key。存储在密码箱 `volcsearch` 中，搜索代码自动读取
- `BAIDU_API_KEY`：百度搜索 API Key（已配置）
- `BRAVE_API_KEY`：Brave Search API Key（已配置）
- OpenClaw 模型调用权限
- `DEEP_RESEARCH_MODEL`：（可选）AI 模型名称，默认 `deepseek-v4-pro`。可通过 CLI `--model` 参数覆盖

### 搜索源优先级

| 优先级 | 搜索源 | 特点 | 限制 |
|--------|--------|------|------|
| 1 | 火山引擎 | 中文优化，5000次免费额度，无需 VPN | 5 QPS 限流 |
| 2 | Firecrawl | 最佳质量，带网页内容抓取 | ⚠️ 免费额度有限 |
| 3 | 多引擎抓取 | Bing CN Web抓取，补充索引覆盖 | HTML解析，稳定性一般 |
| 4 | 百度搜索 | 中文优化，无需 VPN | - |
| 5 | Brave Search | 国际搜索 | 需要 VPN |

## 快速开始

### 基本使用
```bash
deep_research "你的研究主题"
```

### 自定义参数
```bash
# 指定广度（每次研究的搜索查询数量，默认7）和深度（递归层数，默认3）
deep_research "你的研究主题" --breadth 6 --depth 2
```

### 输出说明
- 研究过程中会实时展示进度
- 报告末尾自动包含所有参考来源的完整URL链接
- 默认自动保存到技能的 `output/` 目录，文件名使用报告标题自动生成（替换特殊字符为安全字符）
- 支持自定义输出路径：`--output ./my-report.md`，指定后会保存到你指定的路径

## 核心流程

### 计划驱动模式（默认）

1. **创建工作目录**：从查询生成主题名，建立 `research/<主题>/src/|work/|output/` 目录结构
2. **提示词扩写**：AI 自动检测研究方向（市场雷达/技术拆解），将简短 query 扩写为结构化研究任务书（可选，`--no-expand` 跳过）
3. **问题分析**：AI 分析扩写后的研究任务书，匹配预设研究角度模板，生成推荐研究维度
4. **维度确认**：CLI 交互（y/d/a/p/e）让用户增删、调整优先级、补充自定义维度
5. **反思审核**：AI 以审核人角色检查维度完整性（gap/overlap/ambiguity/missing-perspective），提出追问
6. **计划细化**：AI 为每个维度填充子主题、搜索关键词、广度/深度分配
7. **报告大纲生成**：AI 根据计划生成报告章节结构，用户确认后开始搜索
8. **素材收集**：交互询问用户提供参考 URL 和本地文件；Obsidian 笔记自动用搜索关键词搜索。AI 提取素材中的关键信息作为预加载 learnings
9. **按计划搜索**：全局并发控制下，按维度/子主题并行搜索，预加载素材与搜索结果合并，递归深入
10. **报告生成**：按大纲逐章节填充内容，整合所有学习来源，生成结构化报告
11. **结果输出**：展示报告并保存到归档目录和 output/ 目录

### 直接模式（`--no-plan`）

1. **需求确认**：基于初始查询生成后续问题，收集用户详细需求
2. **深度研究**：自动生成搜索查询 → 并行搜索 → 提取关键信息 → 递归深入
3. **报告生成**：整合所有学习内容，生成结构化研究报告
4. **结果输出**：展示报告并保存到本地文件

## 配置参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `query` | 研究主题/初始查询 | 必填 |
| `--breadth` | 研究广度：每次迭代生成的搜索查询数量 | 12 |
| `--depth` | 研究深度：递归搜索的层数 | 3 |
| `--output` | 报告输出路径 | ./report.md |
| `--no-interactive` | 禁用交互模式，直接使用初始查询开始研究 | false |
| `--no-plan` | 跳过计划流程，使用原有直接研究模式 | false |
| `--concurrency` | 全局搜索并发数（1-10） | 3 |
| `--no-cache` | 禁用搜索缓存 | false |
| `--cache-ttl` | 搜索缓存有效期（秒） | 86400（24h） |
| `--urls` | 逗号分隔的参考 URL 列表 | 空 |
| `--files` | 逗号分隔的参考文件路径列表 | 空 |
| `--no-obsidian` | 禁用 Obsidian 笔记自动搜索 | false |
| `--obsidian-vault` | 指定 Obsidian vault 路径（空=自动检测） | 自动检测 |
| `--direction` | 提示词扩写方向：auto(自动检测)/radar(市场雷达)/deepdive(技术拆解)/general(通用) | auto |
| `--no-expand` | 跳过提示词扩写步骤 | false |
| `--model` | AI 模型名称（如 `deepseek-v4-flash`），覆盖 `DEEP_RESEARCH_MODEL` 环境变量 | `deepseek-v4-pro` |
| `--resume` | 断点续传：自动检测最近一次研究的工作目录，从上次中断处继续 | false |
| `--from-workspace` | 指定已有工作目录路径，从该目录的中间状态继续研究 | 空 |

## 研究归档目录

每次研究自动创建归档目录：

```
research/<主题名-时间戳>/
  ├── src/              # 输入素材
  │   ├── urls/         # URL 抓取的 markdown
  │   ├── files/        # 用户参考文件（转换后 md）
  │   └── obsidian/     # Obsidian 匹配笔记
  ├── work/             # 加工过程
  │   ├── expansion.json
  │   ├── analysis.json
  │   ├── dimensions.json
  │   ├── plan.json
  │   ├── outline.json
  │   ├── learnings.json
  │   └── sources.json
  └── output/           # 输出
      └── report.md
```

## 应用场景

- 学术研究：快速收集整理领域研究资料
- 市场调研：分析市场趋势和竞争对手信息
- 技术评估：深入了解特定技术的发展和应用
- 信息收集：针对特定主题的全面信息收集整理
