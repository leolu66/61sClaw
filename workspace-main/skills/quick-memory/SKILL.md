# Quick Memory - 快速记忆

## 需求说明（SRS）

### 触发条件
- **自动保存**：用户发送任何描述灵感/想法/待办等的消息 → 自动分类存储
- **手动搜索**：消息包含"查记忆""搜记忆""找记忆""搜索""查找记忆"等 → 搜索已存记忆
- **列表查看**：消息包含"最近记忆""我的记忆""记忆列表""所有记忆"等 → 列出最近记忆

### 功能描述
- 用户通过QQ发送想法/灵感/备忘 → LLM自动分类、打标签、加时间戳 → 保存为Markdown文件
- 用户想检索以前的记忆 → 按关键词/标签/日期/分类搜索
- 用户想回顾最近记录 → 列出最近的记忆列表

### 输入/输出
- **输入**：用户消息（文本/语音转文字）
- **输出**：
  - 保存模式 → 确认信息（记忆标题、分类、标签）
  - 搜索模式 → 匹配的记忆列表（标题+日期+分类+摘要）
  - 列表模式 → 最近的记忆概览

### 分类体系
LLM自动从以下分类中选择最匹配的一类：
| 分类 | 说明 | 示例 |
|------|------|------|
| 💡 灵感 | 创意、想法、点子 | "做个AI日历助手" |
| 📝 待办 | 需要做的事 | "明天记得交报告" |
| 📖 笔记 | 学习笔记、知识记录 | "Python异步编程要点" |
| 📌 备忘 | 重要信息、提醒 | "房东电话138xxxx" |
| 🤔 想法 | 思考、观点、感悟 | "我觉大数据太烧钱了" |

### 存储格式
每条记忆保存为单独MD文件，含YAML元信息：

```markdown
---
id: YYYYMMDD-HHmm-序号
date: 2026-06-02 10:08
category: 灵感
tags: [AI, 产品]
title: 标题
source: voice | text
---

具体内容...
```

### 依赖条件
- Obsidian LLM Wiki 的 `raw/灵感速记/` 目录必须存在（路径：`D:\Users\luzhe\Documents\llm-wiki\raw\灵感速记`）
- 可通过 `scripts/config.json` 的 `memory_dir` 修改存储路径
- 无需外部API或数据库
- **依赖技能**: 无（独立技能）

### 边界情况
- 空消息/无意义消息 → 提示用户输入有效内容
- 搜索无结果 → 提示未找到
- 大量记忆（>100条）→ 按最近时间排序，分页展示前10条
- 文件读写失败 → 提示错误信息

### 配置修改
如需更改存储路径，编辑 `scripts/config.json`：
```json
{
  "memory_dir": "D:\\Users\\luzhe\\Documents\\llm-wiki\\raw\\灵感速记",
  "default_list_limit": 10
}
```

### scripts/memory_ops.py
文件操作脚本，提供以下功能：

```python
# 列出所有记忆（按时间倒序，支持分页）
python scripts/memory_ops.py list --limit 10

# 搜索记忆文件（关键词全文搜索）
python scripts/memory_ops.py search "关键词" --limit 10

# 按日期范围筛选
python scripts/memory_ops.py list --from 2026-06-01 --to 2026-06-30

# 统计信息
python scripts/memory_ops.py stats
```

## 工作流程

### 流程1：保存新记忆
```
用户消息 → 判断意图（非搜索=保存）
  → LLM提取内容→分类→打标签→生成标题
  → memory_ops.py 保存文件
  → 返回确认（标题+分类+标签+时间戳）
```

### 流程2：搜索记忆
```
用户消息（含搜索意图）
  → memory_ops.py 列出所有记忆文件
  → 读取文件内容
  → LLM匹配用户搜索意图
  → 返回匹配结果列表
```

### 流程3：最近记忆
```
用户消息（含列表意图）
  → memory_ops.py list --limit 10 获取最新10条
  → LLM格式化展示
```

## 注意事项

1. **记忆文件永不删除** - 只追加不修改，保留完整历史
2. **ID唯一性** - 使用时间戳+序号防重复
3. **搜索依赖LLM** - 语义匹配质量取决于当前模型
4. **语音消息** - QQ语音会自动转为文字（由平台ASR处理）
5. **不要修改已有记忆文件** - 每次都是新建文件
