## 一、知识工程的历史脉络

在人工智能的版图中，知识工程从未缺席。它经历了三个标志性的历史阶段：

第一阶段是专家系统时代。以"If-Then"规则为核心，研究者尝试将人类专家的经验编码为计算机可执行的规则集合。这一阶段的知识是显式的、符号化的，但受限于规则的刚性与知识获取的瓶颈，专家系统最终走向式微。

第二阶段是知识图谱时代。以三元组（实体-关系-实体）为基本单元，知识图谱实现了大规模结构化知识的组织与检索。谷歌、百度、阿里等互联网巨头纷纷构建自有知识图谱，赋能搜索、问答、推荐等核心业务。知识图谱的崛起，让机器第一次拥有了对世界的"结构化认知"。

第三阶段，也就是当下，是大模型时代。预训练大语言模型（LLM）凭借海量语料的自监督学习，将知识以隐式参数的形式编码于数十亿乃至数千亿个神经网络权重之中。知识不再是显式的符号，而是分布式的语义表征。

---

## 二、大模型时代知识工程的四大阶段

王昊奋教授将大模型时代的知识工程划分为四个递进的工程范式，清晰勾勒出这一领域的演化轨迹。

### 2.1 Post-Training 阶段的知识工程

Post-Training（后训练）阶段，是指在大模型基座完成预训练之后，通过合成数据驱动的方式，将特定领域知识与复杂任务能力注入模型。这一阶段的核心命题是：如何让通用大模型具备对专业领域的深度识别与理解能力？

典型路径包括两条主线：

其一，面向 SFT 的指令合成。 基于结构化领域知识（如知识图谱、专业文档、规则库），通过模板填充、知识驱动的改写、多步推理链构造等手段，合成高质量的领域指令-响应对。这些合成数据使模型习得医疗、法律、金融等垂直领域的专业表达范式与概念关联，实现从"通用语言"到"专业语言"的迁移。

其二，面向 Agent 的轨迹合成。 利用任务环境的结构化特性（如 API 调用规范、工具链拓扑、状态转移图），合成包含思考过程（thought）、工具调用（action）、环境反馈（observation）的完整决策轨迹。这些合成轨迹作为强化学习的训练信号，引导模型在复杂多步任务中学会规划、纠错与自适应执行，而非依赖人类标注的偏好反馈。

Post-Training 阶段的合成数据工程，本质上是一种"结构化知识的外化与再内化"——先将领域专家知识的结构特性抽取为可计算的数据生成规则，再以参数化的方式让模型习得对复杂模式与逻辑链条的识别和理解能力。

### 2.2 Prompt Engineering 阶段的知识工程

Prompt Engineering（提示工程）阶段，标志着知识工程从"模型内部"走向"模型接口"。

研究者发现，通过精心设计的提示词，可以在不修改模型参数的情况下，激活模型内部的隐性知识，甚至引导模型进行复杂推理。典型技术包括：

* 思维链提示（Chain-of-Thought, CoT）：通过示例引导模型逐步拆解推理过程；
* 少样本提示（Few-shot Prompting）：在提示中嵌入少量示例，帮助模型理解任务意图；
* 角色扮演提示：为模型赋予特定专家角色，激活相关领域的知识响应模式；
* 指令工程：通过结构化指令约束模型输出的格式与内容。

Prompt Engineering的本质，是将知识工程的重心从"知识存储"转移到"知识激活"——如何用最少的输入，换取最大化的知识输出。

### 2.3 Context Engineering 阶段的知识工程

随着大模型应用的深入，单纯的提示工程逐渐暴露出其局限性：模型的参数化知识存在时效性问题、幻觉问题，以及领域覆盖不足的问题。

Context Engineering（上下文工程）应运而生。其核心思想是：将外部知识动态注入模型的上下文窗口，使模型在推理时能够"即时查阅"最新、最准确的知识。

这一阶段最具代表性的技术是检索增强生成（Retrieval-Augmented Generation, RAG）。RAG的基本框架包括：

* 知识库构建：将文档、知识图谱、数据库等外部知识源进行向量化索引；
* 语义检索：根据用户查询，从知识库中检索最相关的知识片段；
* 上下文拼接：将检索结果与原始查询拼接为模型输入；
* 生成输出：模型基于增强后的上下文生成回答。

在此基础上，GraphRAG等融合知识图谱的高阶RAG方案进一步提升了知识检索的结构化程度与推理深度。Context Engineering的出现，使知识工程从"模型内部的静态参数"延伸至"外部动态知识流"。

### 2.4 Harness Engineering 阶段的知识工程

Harness Engineering（工具链工程）代表了知识工程在大模型时代的最新前沿。

在这一阶段，大模型不再是被动的知识查询终端，而是主动的知识处理与推理智能体（Agent）。知识工程的核心从"如何向模型提供知识"，升级为"如何让模型自主调用工具、协同多源知识完成复杂任务"。

典型的Harness Engineering包括：

* 工具调用（Tool Use/Function Calling）：模型能够自主识别何时调用外部工具（如知识图谱查询接口、数据库API、搜索引擎），并将工具返回结果整合入推理链路；
* 多智能体协作（Multi-Agent Collaboration）：多个专业化Agent分工协作，分别负责知识检索、逻辑推理、结果验证等环节；
* 记忆管理（Memory Management）：对话历史、任务状态、用户偏好等信息的结构化管理，使Agent具备跨会话的长期记忆能力；
* 规划与反思（Planning & Reflection）：Agent能够对复杂任务进行分解规划，并在执行过程中自我反思与修正。

Harness Engineering标志着知识工程进入"知识自主化"时代——知识不再需要人工显式提供，而是由智能体按需自主获取与整合。

---

## 三、知识形态的演化

伴随上述工程范式的迭代，知识的表示形态也在发生根本性变化。

传统知识工程中，知识以规则、本体、三元组等显式符号形式存在，具有高度可解释性，但表达能力有限。

在大模型时代，知识形态呈现出多元融合的趋势：

* 参数化知识（Parametric Knowledge）：编码于模型权重中的隐式知识，覆盖面广但难以精准控制；
* 结构化知识（Structured Knowledge）：知识图谱、关系数据库等形式，具有强逻辑性与可查询性；
* 非结构化知识（Unstructured Knowledge）：文本、图像、音视频等多模态内容，借助大模型实现语义理解；
* 过程化知识（Procedural Knowledge）：以工具调用链、任务规划树等形式表达的操作性知识；
* 情境化知识（Contextual Knowledge）：基于对话历史与用户状态动态生成的个性化知识。

这五类知识形态相互补充、动态交织，共同构成大模型时代的知识生态系统。

---

## 四、新范式：自构建、自演化的知识系统

王昊奋教授提出了一个令人振奋的前沿命题：未来的知识系统，将从"人工构建"走向"自构建、自演化"。

在这一新范式下，知识系统具备以下核心能力：

* 自动知识抽取：从海量非结构化数据中自动识别实体、关系与事件，构建结构化知识；
* 知识自动更新：实时监测外部世界的变化（新闻、学术论文、市场数据等），动态更新知识库；
* 知识一致性维护：自动检测并解决知识库中的矛盾与冗余，保证知识质量；
* 知识驱动推理：基于已有知识进行归纳、演绎与类比推理，自动发现新知识；
* 跨域知识融合：打通不同领域、不同格式的知识壁垒，实现知识的跨域迁移与融合。

这一愿景的实现，将彻底改变知识的生产方式——从"人工著作权"到"AI协同创作"，从"静态数据库"到"动态知识生命体"。

---

## 五、未来展望与总结

站在2026年的历史节点上回望，知识工程的演化轨迹清晰可见：

* 知识的表示从显式走向隐式，再走向显隐融合；
* 知识的构建从人工走向半自动，再走向全自动；
* 知识的应用从静态查询走向动态推理，再走向主动生成；
* 知识系统的角色从工具走向助手，再走向协作智能体。

大模型没有终结知识工程，而是给了它一次凤凰涅槃的机会。知识工程的核心价值——让机器真正"理解"世界、"推理"世界，从未像今天这样接近实现。

对于企业技术团队而言，把握知识工程的新范式，意味着在AI竞争格局中占据先机：

* 构建企业专属知识图谱，与LLM深度融合，实现知识资产的最大化利用；
* 探索RAG、GraphRAG等技术路线，在垂直领域打造高精准度的知识问答系统；
* 布局Agentic AI架构，让知识系统具备自主获取、整合与演化的能力；
* 关注知识系统的可解释性与可审计性，满足监管合规与业务可信度要求。

对于研究机构而言，知识工程与大模型的交叉领域正在涌现大量原创性课题：知识幻觉的检测与修正、知识时效性的维护机制、多模态知识的统一表示框架，以及知识驱动的科学发现……

对于投资者而言，知识工程基础设施（知识图谱平台、RAG中间件、Agent框架）正在成为企业AI转型的关键底座，具有巨大的市场空间与技术壁垒。

---

正如王昊奋教授在文末所言：

"知识工程已死，知识工程万岁。

这不是一句矛盾的口号，而是一次范式的跃迁。

大模型没有杀死知识工程，而是让它以更强大、更智能的方式重生。"
