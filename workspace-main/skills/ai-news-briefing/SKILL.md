# AI新闻简报生成器

基于已采集的AI新闻文件，生成面向运营商运营支撑系统的一页式简报。

## 需求说明（SRS）

### 触发条件

- "AI新闻简报"
- "生成AI简报"
- "AI新闻分析"
- "AI新闻周报"
- "分析AI新闻"
- "AI新闻总结"
- "AI动态简报"

### 功能描述

读取 `ai-news-fetcher/output` 和 `ai-news-collectors*/output` 目录中指定日期之后的新闻文件，分析新闻内容并生成面向**运营商运营支撑系统**的一页式简报。

简报核心框架：**看结论、看影响、看动作**。

### 输入/输出

- **输入**: 起始日期（如 "2026-04-26"），可省略，默认最近30天
- **输出**: `skills/ai-news-fetcher/output/briefing_YYYYMMDD-YYYYMMDD.md`

### 依赖条件

- 新闻文件存在于以下目录：
  - `skills/ai-news-fetcher/output/*.md`
  - `skills/ai-news-collectors*/output/*.md`（如果存在）
- 无外部API依赖

### 边界情况

- 新闻目录不存在 → 提示用户先采集新闻
- 日期范围内无新闻 → 提示无新闻可分析
- 文件内容异常 → 跳过该文件，在附录中标注

## 工作流程

### 第一步：列出新闻文件

搜索以下目录中指定日期之后的 `.md` 文件：

```bash
dir1 = skills/ai-news-fetcher/output/
dir2 = skills/ai-news-collectors*/output/  # 如果存在
```

排除文件名含 `test`、`json` 的非新闻文件。按日期排序，统计文件总数。

### 第二步：读取新闻内容

**优先级策略**：
1. 先读 collector 聚合文件（如有）—— 含评级和分类，信息密度最高
2. 再读最新3天的详细新闻（latest.md + 最近2天）
3. 读最早1天和最中间1天的文件作为趋势对比
4. 如果文件总数 ≤ 10，则全部读取

**读取方法**：使用 `read` 工具读取文件，每个文件约 8-9KB。

### 第三步：提取关键信息

从新闻中提取与运营商运营支撑场景相关的新闻，关注以下维度：

| 维度 | 关键词线索 |
|------|-----------|
| 客服智能化 | 客服、坐席、联络中心、数字员工、Agent |
| 运维自动化 | 运维、自动化、故障诊断、监控、流程 |
| 知识库问答 | 知识库、RAG、问答、文档、检索 |
| 私有化部署 | 私有化、本地部署、安全、合规、信创 |
| 大模型应用 | 大模型、LLM、GPT、DeepSeek、智谱 |
| 成本优化 | 成本、降本、轻量化、推理优化 |
| 政策治理 | 监管、法规、安全、审计 |

对于标题和摘要明显与运营商相关的新闻，使用 `web_fetch` 访问原文获取更多细节。

### 第四步：对重大新闻访问链接

以下类型的新闻需访问链接获取详情：
- 提及运营商（移动/电信/联通/铁塔）的新闻
- 头部AI企业重大发布（OpenAI/Google/Anthropic/DeepSeek/智谱）
- 直接相关的行业应用案例（客服/运维/工单/知识库）
- 容联云、华为云等运营商生态企业的AI动态

### 第五步：生成简报

按 [简报模板](references/briefing-template.md) 格式生成简报。核心要求：

**各章节填写要求**：

1. **核心判断（3句话）**：趋势判断 + 行业影响 + 我司建议，每句不超过50字
2. **TOP10重点新闻**：每条必须有 分类/运营商影响/启示/建议动作 四个字段
3. **机会与风险**：机会从5个维度展开，风险从4个维度展开
4. **建议动作**：每条含 动作/责任方向/优先级/时间建议
5. **结论**：一句话收口，不超过60字
6. **附录**：列出本期覆盖的所有新闻文件

**写作原则**：
- 面向产品线和营销领导，语言简练专业
- 不说"可能"、"或许"等不确定词，不给模棱两可的建议
- 每条新闻都要说清对运营商运营支撑场景的影响
- 每条建议动作都带明确的责任方向和时间

### 第六步：保存输出

简报保存到 `skills/ai-news-fetcher/output/briefing_{start}-{end}.md`。

保存后告知用户文件路径和简报概要（TOP3重点新闻 + TOP1建议动作）。

## 注意事项

1. **不要伪造新闻**：所有新闻必须来自源文件，不在源文件中的内容标注"需确认"
2. **不要泛泛而谈**：每条机会/风险必须有具体新闻支撑
3. **不要遗漏附录**：附录是简报后续可追溯的关键
4. **注意去重**：同一新闻可能出现在多个来源，合并处理
5. **注意时效**：新闻通常标记日期，按日期排列
