# AI 网关深度研究

**研究日期**: 2026-04-15  
**研究主题**: AI 网关的定义、与传统网关和 MaaS 的区别、防火墙关系、核心能力

---

## 一、什么是 AI 网关？

AI 网关（AI Gateway）是专门为管理、路由和优化 AI 模型（特别是大语言模型 LLM）请求而设计的中间件层。它位于应用程序和多个 AI 服务提供商之间，充当统一的接入点。

**核心定位**：AI 网关不是简单的请求转发器，而是针对 AI 工作负载特性（长连接、流式输出、Token 计费、模型差异等）专门优化的智能路由层。

---

## 二、AI 网关 vs MaaS vs 传统云服务网关

| 维度 | 传统 API 网关 | MaaS（模型即服务） | AI 网关 |
|------|--------------|-------------------|---------|
| **设计目标** | 通用 API 管理 | 提供模型推理服务 | 统一管理和优化多源 AI 服务 |
| **主要功能** | 路由、限流、认证、负载均衡 | 模型托管、推理、微调 | 多模型路由、Token 管理、成本控制、Guardrails |
| **计费粒度** | 按请求数/QPS | 按 Token 用量 | 跨提供商统一计量、成本优化 |
| **协议支持** | REST/HTTP 为主 | Provider 特定协议 | 统一 OpenAI 兼容接口，适配多协议 |
| **流式处理** | 有限支持 | 原生支持 | 智能流式管理、中断恢复 |
| **上下文管理** | 无 | 部分支持 | 会话状态、上下文缓存 |
| **典型产品** | Kong, Nginx, AWS API Gateway | OpenAI API, Azure OpenAI | Portkey, Cloudflare AI Gateway, OpenClaw |

### 关键区别

1. **MaaS 是"供应商"**，提供模型能力；**AI 网关是"调度器"**，整合多个 MaaS
2. **传统网关关注"连接"**，AI 网关关注"智能调度"（模型选择、Fallback、成本优化）
3. **AI 网关理解 Token 经济**，传统网关只关心请求数

## 三、防火墙是否属于网关的组件？

**答案是：防火墙和网关是不同层次的安全机制，但在现代架构中常协同工作。**

| 组件 | 层级 | 作用 |
|------|------|------|
| **防火墙** | 网络层 (L3/L4) | 基于 IP、端口、协议的访问控制，阻止未授权连接 |
| **WAF** | 应用层 (L7) | 检测 HTTP 请求中的恶意模式（SQL 注入、XSS 等） |
| **API 网关** | 应用层 (L7) | 路由、认证、限流、协议转换 |
| **AI 网关** | 应用层 + AI 语义层 | 上述全部 + 内容安全、Prompt 注入防护、PII 脱敏 |

### 关系说明

- 防火墙是**基础设施层**的安全边界
- AI 网关包含**应用层安全能力**（Guardrails、内容过滤、PII 脱敏）
- 生产环境中，防火墙在网关**之前**作为第一道防线，网关内置的安全能力作为**第二道防线**

## 四、AI 网关的典型能力

根据 Portkey、Cloudflare AI Gateway、Kong AI Gateway 等主流产品的能力，AI 网关应提供以下核心功能：

### 1. 多模型路由与抽象
- 统一 OpenAI 兼容接口，后端可对接 200+ 模型提供商
- 智能路由：按成本、延迟、可用性自动选择最优模型
- 条件路由：根据请求内容路由到不同模型

### 2. 可靠性与容错
- **自动重试**：指数退避策略，最多 5 次重试
- **Fallback**：主模型失败时自动切换到备用模型
- **负载均衡**：跨多个 API Key 或提供商分发请求
- **超时控制**：精细化请求超时管理

### 3. 成本优化
- **智能缓存**：简单缓存 + 语义缓存，减少重复请求
- **Token 管理**：实时追踪 Token 消耗和成本
- **用量分析**：按模型、按应用、按用户的成本归因

### 4. 安全与合规（Guardrails）
- **输入防护**：Prompt 注入检测、敏感词过滤
- **输出防护**：内容审核、PII 脱敏、合规检查
- **访问控制**：RBAC、API Key 管理、IP 白名单
- **审计日志**：完整请求/响应记录，满足合规要求

### 5. 可观测性
- 实时日志：请求延迟、Token 用量、错误率
- 分布式追踪：与 LangChain、LlamaIndex 等框架集成
- 成本仪表板：可视化 AI 支出

### 6. Agent 与 MCP 支持
- 与主流 Agent 框架集成（AutoGen、CrewAI、LangChain）
- MCP（Model Context Protocol）网关：统一管理工具调用

## 六、总结

| 问题 | 结论 |
|------|------|
| AI 网关是什么？ | 专门管理 AI 模型请求的智能中间件，提供统一接口、路由、安全、成本优化 |
| 与 MaaS 区别？ | MaaS 提供模型能力，AI 网关管理多个 MaaS；网关在上层做调度 |
| 与传统网关区别？ | AI 网关理解 Token 经济、支持流式、有语义层安全能力 |
| 防火墙关系？ | 防火墙是网络层边界，AI 网关是应用层安全；两者互补 |
| 核心能力？ | 多模型路由、可靠性、成本优化、Guardrails、可观测性 |
