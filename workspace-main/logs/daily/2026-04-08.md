# 工作日志 2026-04-08

## 主要工作

### 1. 创建 docx-to-markdown 技能

**需求**: 将 Word 文档（DOCX）转换为 Markdown 格式，支持单文件和批量转换

**实现功能**:
- 单文件转换: `python scripts/convert.py "doc.docx"`
- 批量转换: `python scripts/convert.py "C:\\Docs" --batch`
- 递归转换: `python scripts/convert.py "C:\\Docs" --batch --recursive`
- 指定输出目录: `python scripts/convert.py "C:\\Docs" --batch -O "C:\\Output"`

**转换规则**:
| Word 元素 | Markdown 输出 |
|-----------|--------------|
| 标题 1-6 | `#` - `######` |
| 无序列表 | `- 项目` |
| 有序列表 | `1. 项目` |
| 表格 | Markdown 表格格式 |
| 粗体 | `**文本**` |
| 斜体 | `*文本*` |

**技术要点**:
- 使用 `python-docx` 库读取 DOCX 文件
- 通过段落样式名判断标题级别（Heading 1-6 / 标题 1-6）
- 修复 Windows 控制台编码问题（`sys.stdout = io.TextIOWrapper`）
- 处理粗体/斜体时避免单个字符被分割加粗的问题

**文件**:
- `skills/docx-to-markdown/SKILL.md`
- `skills/docx-to-markdown/scripts/convert.py`

## 遇到的问题

### 1. Windows 控制台编码问题
**现象**: Python 输出中文时出现 `UnicodeEncodeError: 'gbk' codec can't encode character`
**解决**: 在脚本开头添加编码修复
```python
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8')
```

### 2. 粗体格式处理异常
**现象**: 每个字符都被单独加粗（`**模**** ****版**`）
**原因**: 原代码逐个 run 检测格式，导致字符级分割
**解决**: 改为整段检测，只有当整个段落都是粗体/斜体时才添加格式标记

## 开发经验总结

- **编码问题优先处理**: Windows 环境下的 Python 脚本，编码修复应该放在最前面
- **格式检测策略**: 对于 Word 文档，整段格式检测比逐字符检测更可靠
- **技能分层设计**: docx-to-markdown 属于 L3 业务应用层，依赖 python-docx（外部库）
